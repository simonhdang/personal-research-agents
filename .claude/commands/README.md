# Commands

- `/setup`: First-run onboarding: builds your researcher profile, picks your reference manager and email, creates Notion trackers, and processes past manuscripts. Re-run one part with /setup references | soul | accounts | notion | journals.
- `/new-project`: Create a new research project folder from the template, with its own CLAUDE.md, reference group and Notion tracker.
- `/update`: File and learn from anything new: files in inbox/ or a project's submissions/_drop/, pasted text, or a link. Use --refresh to pull outside changes (new publications, citing papers, journal guidelines).
- `/close-project`: Harvest a finished (or rejected) project into reusable vault knowledge after you approve a harvest report, then archive it.
- `/status`: Snapshot across all projects: recent runs, deadlines, what's waiting on coauthors, references to download, and pending suggestions. Use --brief for the Monday research brief.
- `/review`: Simulated pre-submission review of a project's manuscript for a named journal: desk screen, three independent reviewers and a devil's advocate in parallel, then an editor's decision letter.
- `/respond`: Revise-and-resubmit: parse the real reviews for a project's current round, plan responses using what worked before, then draft the response letter, traceability matrix and tracked-change manuscript edits.
- `/analyze`: Plan or run an analysis for a project (experiment, survey, PROCESS, PLS-SEM, CB-SEM, power) locally in R/Python with a reproducible Quarto report.
- `/draft`: Write or revise part of a manuscript in your voice for the target journal; edits become a new tracked-change version and pass the integrity check.
- `/cite-check`: Check every citation in a draft or manuscript against your reference library and PDFs, and report anything missing, ambiguous or without full text.
- `/retro`: Look back: compare simulated reviews with the real ones, see where you overrode the agents, and propose lesson updates and rule suggestions. Runs quarterly or after a decision arrives.
- `/lint`: Vault health check: broken links, orphan pages, stale project status, contradictions, and growth that suggests reorganizing.
